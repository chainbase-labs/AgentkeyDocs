title: "One Unified Key"
description: "A single master key for every provider."
---

Traditionally, connecting an agent to the outside world means signing up for many
separate APIs — each with its own account, auth flow, rate limits, and invoice.
AgentKey replaces all of that with **one master key**.

## What the key handles

<CardGroup cols={2}>
  <Card title="Authentication" icon="lock">
    One credential authorizes every category, on both the MCP server and the
    REST API. No per-provider OAuth or API-key juggling.
  </Card>
  <Card title="Routing" icon="route">
    Scenario Methods pick the upstream provider for you and switch to a backup
    when one fails. Catalog tools run the exact tool you name.
  </Card>
  <Card title="Billing" icon="receipt">
    All usage is covered by one subscription and one invoice, in credits.
  </Card>
  <Card title="Management" icon="sliders">
    Create, rotate, and monitor keys from a single dashboard.
  </Card>
</CardGroup>

## The "before and after"

**Before AgentKey** — your agent is smart but can't reach anything: no live
social data, only surface-web search, no market or on-chain context.

**After AgentKey** — one key, and the agent gets real-time social data, deep web
scraping, e-commerce catalogs, market feeds, filings, weather, travel and
academic search, with provider failover built into the fixed-contract methods.
