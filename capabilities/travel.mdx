The **Travel** category lets an agent plan a trip: find destinations and
airports, search hotels, rooms and holiday rentals, compare what each booking
site charges, compare flight offers including multi-stop routes, price car
rentals and taxis, and look up attractions and restaurants with their reviews.
All operations are read-only lookups — searching, pricing and detail pages;
none places a reservation.

## Providers

| Provider | Coverage |
| --- | --- |
| **booking** | Hotels: destination search, hotel search by destination or coordinates, filters and sort options, hotel details, description, facilities, photos, policies, payment features, children policies, room list and availability, availability calendar, review scores, reviews and tips, Q&A, nearby cities. Flights: airport search, flight search (one route or multi-stop), flight details, minimum price, seat map. Car rentals: location search, rental search, vehicle details, supplier details, ratings and reviews, booking summary. Attractions: location search, attraction search, details, reviews, popular nearby. Taxis: location search and taxi search. Utilities: currencies, exchange rates, languages, address to lat / long |
| **AnyAPI** | Airbnb: listing search by location and dates with price, bed, bedroom, bathroom and guest filters. Google Hotels: hotel search by destination and dates, hotel details with the price from each booking site, amenities and check-in times. Tripadvisor: hotel, restaurant and attraction search, the latest reviews of a place. Booking.com: stay search by destination, dates and occupancy, as a second route alongside **booking** |

AnyAPI tools are named `AnyAPI/<platform>_<operation>` (for example
`AnyAPI/airbnb_search`) and sit under `travel/airbnb`, `travel/google-hotels`,
`travel/tripadvisor` and, with the booking tools, `travel/booking`. The
per-call cost is shown by `describe_tool`.

<Note>
  **Building with code?** Developers and enterprise integrations can call this
  category through [Scenario Methods](/api-reference/scenario/overview): fixed
  REST contracts with a stable schema, a fixed price and automatic provider
  failover. The methods are listed by platform in the API Reference sidebar.
</Note>

## Browse the catalog

```text
find_tools(prefix="travel")
find_tools(q="hotels in Lisbon for two adults, 12 to 15 November")
describe_tool("booking/Search_Hotels")
execute_tool("booking/Search_Hotels", { ...params })   # copy describe_tool's execute_as
```

<Note>
  Most booking tools expect an identifier from an earlier search — a destination
  id, hotel id, airport code or location id — so chain
  `Search_Hotel_Destination` → `Search_Hotels` → `Get_Hotel_Details` rather
  than calling a detail tool cold. `describe_tool` shows which ids each one
  needs.
</Note>
