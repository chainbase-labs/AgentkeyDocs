The **Scrape** category fetches a page and returns content your agent can use
directly. It is small — four tools from three providers — so the choice is
mostly about how hard the target page is to reach.

## Providers

| Tool | What it does |
| --- | --- |
| `Firecrawl/scrape` | Scrape a single URL; optionally extract structured information with an LLM |
| `Jina/readUrlGet` | Read a URL by prefixing it with `https://r.jina.ai/` — the lightest way to get a page as text |
| `Jina/readUrlPost` | The same reader with the URL in a JSON body; accepts the `x-*` header options |
| `BrightData/unlock` | Fetch a URL through the Web Unlocker for challenge-gated sites; returns the target site's raw response wrapped in JSON |

## Choosing a tool

- Start with **Firecrawl** or **Jina Reader** for ordinary pages.
- Fall back to **BrightData Web Unlocker** only when a page is protected by
  anti-bot challenges — it returns the raw response, not cleaned text.
- Need many URLs or a whole site? `Tavily/post_extract`, `Tavily/post_crawl`
  and `Tavily/post_map` live in the [Search](/capabilities/search) category.

<Note>
  **Building with code?** Developers and enterprise integrations can call this

## Browse the catalog

```text
find_tools(prefix="scrape")
find_tools(q="get the main article text from https://example.com/post")
describe_tool("Firecrawl/scrape")
execute_tool("Firecrawl/scrape", { url: "https://example.com/post" })
```

<Note>
  Parameters and per-call cost differ between the four tools — check
  `describe_tool` before executing. `execute_tool` calls exactly the tool you
  name; switching to another scraper on failure is your call, not automatic.
</Note>
