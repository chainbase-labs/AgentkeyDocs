The **Crypto** category gives agents real-time market and on-chain data — token
prices and rankings, wallet holdings and history, token holders and transfers,
NFTs, DEX pools, exchange derivatives, prediction markets, crypto news and
social mindshare — from four providers behind one key.

## Providers

| Provider | What it brings |
| --- | --- |
| **Surf** | Exchange order books, funding, long/short ratios, liquidations and options; Polymarket and Kalshi markets, prices, order books, trades and smart money; social mindshare, sentiment and smart-follower history; wallet detail, net worth, protocol positions and labels; token holders, transfers, DEX trades and unlock schedules; DeFi, bridge and yield rankings; fund profiles and portfolios; news feed plus cross-cutting search over projects, funds, wallets, posts, airdrops and the web; on-chain SQL and structured queries |
| **CoinMarketCap** | Listings and quotes (latest and historical), K-line candles, CMC20 / CMC100 indices, Fear & Greed, global metrics; DEX pairs, pools, token prices, liquidity and holders; exchange metadata and assets; categories, airdrops, ID maps |
| **Chainbase** | On-chain primitives: native and ERC-20 balances, account transactions and NFTs, token metadata, holders and transfers, token price and history, NFT collections, items, owners and transfers, ENS resolve / reverse, latest block, block and transaction lookup |
| **PANews** | Crypto news articles, 24h and weekly rankings, daily must-reads, series and topics, article search, industry calendar and events |

## Sub-categories

Every crypto tool carries one of these tags, which `find_tools` uses when
ranking:

| Group | What it covers |
| --- | --- |
| **Market Data** | Live quotes, listings, rankings, K-lines, indices, ETF flows, Fear & Greed, on-chain indicators, token price history |
| **CEX & Derivatives** | Exchange pairs, tickers, order-book depth, OHLCV, perpetual snapshots, funding history, long/short ratios, liquidations, options |
| **DEX Pools** | Spot pairs, pool quotes, swap lists, token liquidity, holder counts and trends, security detail, yield rankings |
| **Token Analytics** | Metadata, holders and top holders, transfers, DEX trade history, unlock schedules |
| **NFTs** | Collections, items, metadata, owners and owner history, transfers |
| **Wallets** | Balances, ERC-20 and NFT holdings, transactions, transfers, net worth, DeFi protocol positions, address labels |
| **Chain Primitives** | Latest block, block and transaction lookup, gas price, on-chain SQL and structured queries |
| **Naming Services** | ENS resolve and reverse lookup |
| **Crypto News** | News feeds and articles, rankings, must-reads, series, topics, project AI news |
| **Industry Events** | Calendar events, conferences and activities, exchange listings, TGEs, public sales, airdrops |
| **Social Intelligence** | Mindshare rankings and time series, engagement scores, sentiment, smart followers, social user profiles and posts |
| **Prediction Markets** | Polymarket and Kalshi events, markets, prices, OHLCV, order books, trades, volumes, open interest, leaderboards, cross-platform matching |
| **Projects & Funds** | Project detail and DeFi metrics, protocol and bridge rankings, fund profiles, portfolios and rankings, categories |
| **Crypto Search** | Search over projects, funds, wallets, news, social posts and people, airdrops, prediction markets and the web |

<Note>
  **Building with code?** Developers and enterprise integrations can call this
  category through [Scenario Methods](/api-reference/scenario/overview): fixed
  REST contracts with a stable schema, a fixed price and automatic provider
  failover. The methods are listed by platform in the API Reference sidebar.
</Note>

## Browse the catalog

```text
find_tools(prefix="crypto")
find_tools(q="ERC-20 balances held by wallet 0xabc... on Ethereum")
describe_tool("Chainbase/GetAccountTokens")
execute_tool("Chainbase/GetAccountTokens", { ...params })      # copy describe_tool's execute_as
```

<Note>
  Prediction-market, derivatives and social-intelligence tools are deep and
  parameter-heavy — always `describe_tool` first. The per-call cost is shown
  there too.
</Note>
