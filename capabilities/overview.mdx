category. Each tool is named `Provider/Operation` and is reached through the
same [discover → describe → execute](/concepts/discover-describe-execute) flow.

## At a glance

| Category | Discover with |
| --- | --- |
| Search | `find_tools(prefix="search")` |
| Scrape | `find_tools(prefix="scrape")` |
| Social | `find_tools(prefix="social")`, or one platform: `find_tools(prefix="social/twitter")` |
| Crypto | `find_tools(prefix="crypto")` |
| Finance | `find_tools(prefix="finance")` |
| Business | `find_tools(prefix="business")` |
| E-commerce | `find_tools(prefix="ecommerce")` |
| Weather | `find_tools(prefix="weather")` |
| Travel | `find_tools(prefix="travel")` |
| Jobs | `find_tools(prefix="jobs")` |
| Academic | `find_tools(prefix="academic")` |
| Developer | `find_tools(prefix="developer")`, or `find_tools(prefix="developer/github")` |
| Account | `execute_tool("agentkey_account")` — free |

Browsing by prefix is for orientation. When you know what you want, pass the
intent straight to `find_tools(q="...")` and it ranks matches across every
category; combine `q` and `prefix` to search inside one subtree.

<Tip>
  The catalog grows as providers are added. Discover with `find_tools` at run
  time rather than hard-coding tool names.
</Tip>

<Note>
  **Building with code?** Developers and enterprise integrations can call the
  same categories through [Scenario Methods](/api-reference/scenario/overview):
  fixed REST contracts with a stable schema, a fixed price and automatic
  provider failover. See [Two Ways to Call](/concepts/two-ways-to-call).
</Note>
