title: "Quickstart"
description: "Read the catalog, describe a method, and make your first call — three curl commands."
---

You need an AgentKey master key (`ak_...`) from the
[console](https://console.agentkey.app). Only the third step uses it; the catalog
and describe are public.

<Steps>
  <Step title="Find a method in the catalog">
    List the methods for one platform. Filter with `domain`, `platform` and
    `action`, or omit them for everything.

    ```bash
    curl "https://api.agentkey.app/v2/ops?domain=social&platform=x"
    ```

    ```json
{
  "methods": [
    {
      "name": "social.x.post.comments",
      "version": 1,
      "tier": "beta",
      "domain": "social",
      "platform": "x",
      "action": "post.comments",
      "summary": "List comments on a X (Twitter) post. Returns a normalized Comment page.",
      "price_credits": 0.2,
      "providers": [
        "tikhub",
        "sorsa"
      ]
    },
    {
      "name": "social.x.post.get",
      "version": 1,
      "tier": "beta",
      "domain": "social",
      "platform": "x",
      "action": "post.get",
      "summary": "Fetch one public post on X (Twitter) by ID or URL. Returns a normalized Post.",
      "price_credits": 1,
      "providers": [
        "sorsa",
        "tikhub"
      ]
    },
    "…"
  ]
}
    ```

    Every entry gives you the name to call, its tier, the fixed price in credits
    and the providers behind it.
  </Step>

  <Step title="Describe the method">
    Describe returns the exact input schema, the output schema, the reserved
    parameters, and each provider with its live health, the fields it cannot
    supply and a recorded example response.

    ```bash
    curl https://api.agentkey.app/v2/ops/social.x.post.search
    ```

    ```json

  "name": "social.x.post.search",

    ```

    The same schema is on the method's page in the sidebar and in the OpenAPI
    document at `/v2/openapi.yaml`.
  </Step>

  <Step title="Call it">
    Send the parameters as JSON with your key as a bearer token.

    ```bash
    curl https://api.agentkey.app/v2/ops/social.x.post.search \
      -H "Authorization: Bearer $AGENTKEY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"query": "from:NASA", "sort": "latest", "limit": 5}'
    ```

    The response is the [success envelope](/api-reference/scenario/responses):
    who served it, what it cost, every attempt, and the normalized `Post` page
    in `data`.

  </Step>

  <Step title="Get the next page">
    Repeat the call with the same parameters plus the `cursor` from
    `data.next_cursor`. The cursor keeps you on the same provider.

    ```bash
    curl https://api.agentkey.app/v2/ops/social.x.post.search \
      -H "Authorization: Bearer $AGENTKEY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"query": "from:NASA", "sort": "latest", "limit": 5, "cursor": "<next_cursor>"}'
    ```
  </Step>

  <Step title="Pin a provider (optional)">
    When you need one specific provider — to compare, or because it has a field
    the default one lacks — name it. The price does not change.

    ```bash
    curl https://api.agentkey.app/v2/ops/social.x.post.search \
      -H "Authorization: Bearer $AGENTKEY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{"query": "from:NASA", "limit": 5, "provider": "tikhub"}'
    ```
  </Step>
</Steps>

<Note>
  Response bodies above are recorded examples with text and handles redacted;
  live responses carry the real content. The `request_id` is illustrative.
</Note>

## Generate a client

The OpenAPI 3.1 document covers every public method with full request and
response schemas, so any OpenAPI code generator can produce a typed client:

```bash
curl -o agentkey-v2.yaml https://api.agentkey.app/v2/openapi.yaml
```
